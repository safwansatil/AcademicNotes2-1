We can not connect i/o with system bus.  I/O module is used for this.<br>
This is the principle of separation of concerns. The CPU focuses on computation, while specialized I/O controllers handle device-specific details.

```text

         (Scan to ASCII)   (Standard bus format)
        
Hard Drive → SATA Controller → System Bus → CPU
           (Sectors to blocks) (Standard bus format)
           
Network → Ethernet Controller → System Bus → CPU
        (Packets to data)     (Standard bus format)
```

Summary:
Why no direct connection? **Three core reasons:**

Diversity Problem: Thousands of device types with unique operations → Can't build all logic into CPU

Speed Problem: Ranges from 10 bytes/sec to 1 TB/sec → Direct connection wastes resources or loses data

Protocol Problem: Different data formats, word lengths, timing → Need protocol conversion

**The Architecture Solution:**

I/O Controllers/Interfaces act as translators and buffers

System Bus provides standardized communication between CPU and controllers

Three transfer methods:

Programmed I/O: CPU manages everything (slow devices)

Interrupt-driven I/O: Device notifies CPU (medium speed)

DMA: Controller transfers directly to memory (high speed)

---

The I/O module speaks two languages:

To CPU: Standard system bus protocol

To Device: That specific device's weird protocol
